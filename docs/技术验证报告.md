# 技术验证报告 · DSH 子代理陪玩后端

本文件记录为《项目框架方案》所做的全部实测，结论均来自本机真实运行，不是推测。
环境：Windows / DeepSeek Harness 0.2.1-rc.2 桌面版 / Node v24.21.0。

---

| 项 | 路径 |

| CLI 启动器 | C:/DeepSeek Harness/resources/runtime/cli/bin/dsh.cmd |

CLI 启动器实际执行的是：`set ELECTRON_RUN_AS_NODE=1` 后用 Electron 可执行文件以 Node 模式跑 cli.js。
因此业务代码里不要依赖 `node` 在 PATH 上，要么用随包的 node.exe，要么用 `DeepSeek Harness.exe + ELECTRON_RUN_AS_NODE=1`。

## 2. 后端接入方式的选择

DSH 有四种可编程形态：

| 形态 | 启动 | 协议 | 适用 |
| --- | --- | --- | --- |
| sdk（stdio JSON-RPC） | `--profile sdk` | JSON-RPC 2.0 over stdio | 我们要的：进程内多 session |
| sdk-minimal | `--profile sdk-minimal` | 同上，树更小、无多余工具 | **推荐底座** |
| headless | `--profile headless "task"` | 一次性，NDJSON 到 stdout | 不适合多轮对局 |
| web-app | `--profile web --port 8080` | 浏览器 GUI + Host API | 前端是它自己的 GUI，耦合内部契约 |

结论：**走 sdk-minimal + stdio JSON-RPC**。1518 端口的 Host API 是 Web GUI 的内部 Typert RPC（每次调用要带 peer、有 remoteAccess 判定），第三方前端接它属于逆向内部契约，不采用。

## 3. 实测：账号复用（不需要 API Key）

patch 里插入四个插件即可复用桌面端已登录的 DeepSeek 账号：

```yaml
- insert:
    - id: credentials
      name: '@deepseek-ai/dsh-credentials-local'
      config:
        path: '%USERPROFILE%/.dsh/.credentials.yaml'
        watch: false
    - id: authorization
      name: '@deepseek-ai/dsh-authorization'
    - id: deepseek-account
      name: '@deepseek-ai/dsh-deepseek-account-platform'
    - id: llm-deepseek-account
      name: '@deepseek-ai/dsh-llm-deepseek-account'
```

`initialize { provider: 'deepseek-account', model: 'deepseek-flash' }` 返回 `serverInfo.name = deepseek-harness-sdk-runtime`；随后 `session/prompt` 收到 `assistant/message` 与 `turn/end`。
环境变量里没有任何 API Key，`~/.dsh/.env` 不存在，登录态只存在于 `.credentials.yaml` 的 `deepseek-account-platform/default`（kind: grant）。

## 4. 实测：并发与上下文隔离

- 同一 runtime 进程内 3 个 sessionId 并行一轮：1976ms / 2723ms。
- 每个 session 独立记住自己的上一轮发言，且只知道自己身份（狼人知道队友、预言家不知道别人的秘密）。
- 12 个 session 并行一轮：2213ms，12/12 全部作答。

**结论：sessionId 就是隔离边界**，不需要额外做权限过滤层。

## 5. 实测：per-agent 工具注册（act）

插件形态（`export const name / inject / apply`）：

- 服务键就是 `tools`：`ctx.get('tools')`。
- 必须监听 `agent/created` 且**解构** `({ agent })`（回调参数是 `{ agent, source }`，直接当 agent 用会 undefined）。
- 注册必须带 `output: { schema, render }`，否则抛 `tool "x" must declare output`。
- 正确写法：`ctx.on('agent/created', ({ agent }) => agent.ctx.tools.register({...}), { global: true })`。

实测 6 座并行捕获 12 次 `act` 调用（speak + vote 各一次），参数是结构化 JSON → 状态机可完全由工具参数驱动，不需要解析自由文本。

## 6. 实测：per-agent 人格注入

`agent.ctx.systemPrompt.section({ name, order, text })`（order 必须是有限数字，同作用域同名重复抛错）。
给两个新 session 注入不同座位身份，分别回答「我是5号玩家，身份是女巫」「2号，狼人，队友是4号」→ 身份隔离生效。

## 7. 实测：局末释放 / 不继承上下文

- 持久化插件是 `sessions`（`@deepseek-ai/dsh-session-persistence-jsonl`）。开启时同一 sessionId 换进程会报 `session "xxx" already exists`，并落盘 `<DSH_HOME>/sessions/<cwd>/<sessionId>/session.v4.jsonl`（24 文件约 0.54MB）。
- 加 `- id: sessions` + `disabled: true` 后：同 sessionId 换新进程，旧暗号完全丢失；新 DSH_HOME 只生成 `profiles/` 与 `.anonymous-user-id`，**不写任何 session 文件**。

**结论：一局 = 一个 runtime 进程 + 一次性临时 DSH_HOME；局末 `shutdown` 后杀进程，整局上下文蒸发。**
JSON-RPC 协议本身没有 per-session close、也没有 prompt-cancel，所以释放粒度只能是进程。

## 8. 实测：工具面裁剪

把下列 id `disabled: true` 后，模型不再去摸环境（此前会先调 `working_directory`/`pwsh` 浪费步骤）：

`tool-fs, tool-working-directory, persistent-bash, persistent-pwsh, terminal-bash, terminal-pwsh, pty, subprocess, jobs, mcp-resources, attachment-local, compaction-basic, image-offload, session-title`

裁剪后 6 座一轮只剩 `act` 调用。

## 10. 事件与元数据

`session.event` 实测出现的类型：
`agent/inbox/spliced, assistant/message, request/context, request/header, session-log-deepseek/delivery-accepted, step/end, step/start, system/message, tool/call, tool/result, turn/end, turn/start, user/message`

- `turn/end`（`reason.kind === 'completed'`）是回合结束信号；`session/prompt` 返回的 messageId 只是入队凭据，不代表回合结束。
- `tool/call` 的 `data` 含 `{ turn, step, callId, name, arguments }`，`arguments` 是 JSON 字符串。
- `assistant/message` 的 content 里有 `{type:'reasoning'}` 与 `{type:'text'}`，可分开取。
- `request/context` 只有 114 字节：`{provider, model, contextWindow: 1048576, systemPromptUpdate:'in-history'}` → **拿不到 token 用量**，计费只能自己按字符估算。

## 11. 失败路径记录（别再踩）

| 尝试 | 结果 |
| --- | --- |
| `ctx.on('ready', ...)` | 不触发，`ready` 不是可监听事件名 |
| `ctx.on('agent/created', (agent) => ...)` | agent 为 undefined，必须解构 `({ agent })` |
| `tools.register({name, description, parameters, execute})` | 抛错，必须带 `output.schema` + `output.render` |
| `--profile desktop --dump-config` | `profile "desktop" is managed exclusively by the Electron application` |
| 复用不存在的 profile 名 | `profile "xxx" does not exist; create it with 'dsh plugin --profile xxx add <package>'` |
| 持久化开启时复用 sessionId | `session "xxx" already exists` |

补充：`--profile sdk-minimal` 可以直接用（打包 bundle 名即可当 profile 名），不必先 `dsh plugin` 建 profile；它会在 DSH_HOME 下自动生成 profiles/sdk-minimal 骨架。

## 12. 推理档位

`dsh-llm` 暴露 `ReasoningEffortId`，实测存在的档位：`off / low / high / max`（`dsh-llm-deepseek/lib/index.js:461-464`）。
`initialize` 参数可带 `reasoningEffort`；不传时取连接默认（deepseek 账号默认 high）。
建议：狼人杀发言用 `low`（延迟与成本更低），关键决策（狼刀/投票/预言家验人）也用 `low`，需要更强推理时再上 `high`。
